## Two ways to reach Shanone programmatically

Most agent integrations should use the [MCP server](/mcp/overview) — it's what Cursor, Claude Code, and other MCP clients speak natively. The REST API documented here is the same underlying functionality, useful when you want to call Shanone directly from a script, backend service, or CI job without an MCP client in the loop. In fact, Shanone's own local stdio MCP proxies (`@duzzle/shanone-mcp` and the Python equivalent) are implemented as thin wrappers over this exact REST API.

## Base URL

```
https://app.shanone.ai/api
```

## Authentication

External API requests (as opposed to the web dashboard's session-based JWT auth) use a Shanone API key:

```bash
curl "https://app.shanone.ai/api/v1/tools/search?query=post+slack+message" \
  -H "Authorization: Bearer sh_xxxxxxxxxxxxxxxx"
```

See [Authentication](/api-reference/authentication) for key management, scoping, and rate limits.

These map directly to the MCP meta-tools of the same shape — `GET /v1/tools/search` is what `shanone_search_tools` calls under the hood, `POST /v1/tools/{tool_name}/execute` is `shanone_execute_tool`, and so on. If you already know the MCP tool you want, the REST endpoint is almost always the same verb aimed at a slightly different URL shape.

<Note>
Shanone's dashboard (Settings, API Keys, Webhooks, Integrations, etc.) is backed by a much larger set of JWT-authenticated internal routes — those aren't part of the external API and aren't meant to be called directly with an API key.
</Note>

## Example: search, then execute

<Tabs>
  <Tab title="cURL">
    ```bash
    # 1. Search
    curl "https://app.shanone.ai/api/v1/tools/search?query=post+slack+message&limit=5" \
      -H "Authorization: Bearer sh_xxxxxxxxxxxxxxxx"

    # 2. Execute
    curl -X POST "https://app.shanone.ai/api/v1/tools/slack_post_message/execute" \
      -H "Authorization: Bearer sh_xxxxxxxxxxxxxxxx" \
      -H "Content-Type: application/json" \
      -d '{"arguments": {"channel": "#general", "text": "Hello from the API!"}}'
    ```
  </Tab>
  <Tab title="Python">
    ```python
    import requests

    headers = {"Authorization": "Bearer sh_xxxxxxxxxxxxxxxx"}
    base = "https://app.shanone.ai/api"

    search = requests.get(f"{base}/v1/tools/search",
                          params={"query": "post slack message", "limit": 5},
                          headers=headers).json()

    result = requests.post(f"{base}/v1/tools/slack_post_message/execute",
                            json={"arguments": {"channel": "#general", "text": "Hello from the API!"}},
                            headers=headers).json()
    ```
  </Tab>
</Tabs>

## Response shape

Tool Vendor and Skill Vendor endpoints return plain JSON objects (not the Markdown-formatted text the MCP tools produce) — e.g. `shanone_search_tools`'s underlying endpoint returns:

```json
{
  "tools": [{ "name": "slack_post_message", "service": "slack", "description": "Post a message to a Slack channel or user." }],
  "total": 1,
  "query": "post slack message",
  "offset": 0,
  "limit": 5,
  "has_more": false
}
```

Execution results follow the same `success` / `reason` / `connect_link` shape described in [Tools Reference](/mcp/tools-reference#error-responses), whether you call `shanone_execute_tool` over MCP or `POST /v1/tools/{tool_name}/execute` over REST.

## Rate limits

| Setting | Default |
|---------|---------|
| Requests per minute | 60 |
| Requests per day | 10,000 |

Both are configurable per API key (up to 1,000/min and 1,000,000/day) from **Settings → API Keys**. Exceeding either returns `429` with a `Retry-After` header.
