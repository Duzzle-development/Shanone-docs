## Tool Vendor

Search, inspect, and execute any of Shanone's 269+ integrations without a dedicated MCP tool per action.

**Recommended workflow:** `shanone_search_tools` (or `shanone_list_service_tools` for a full listing) → `shanone_get_tool_schema` (if needed) → `shanone_execute_tool`.

### shanone_search_tools

Search for integration tools by keyword, relevance-ranked.

<ParamField path="query" type="string" required>
  Natural-language or keyword search. Example: `"post slack message"`, `"create github issue"`.
</ParamField>
<ParamField path="service" type="string">
  Optional service filter, e.g. `"slack"`, `"github"`, `"notion"`.
</ParamField>
<ParamField path="limit" type="integer" default="20">
  Maximum results (max 100).
</ParamField>
<ParamField path="offset" type="integer" default="0">
  Number of matching results to skip, for pagination.
</ParamField>

<Tabs>
  <Tab title="Example Request">
    ```json
    { "query": "post slack message", "service": "slack", "limit": 5 }
    ```
  </Tab>
  <Tab title="Example Response">
    ```
    Showing 1 of 1 matching tool(s) for "post slack message" (service: slack) (offset=0):

    - **slack_post_message** (slack)
      Post a message to a Slack channel or user.

    **Next steps:**
    1. Use `shanone_get_tool_schema` to see the input schema for a tool
    2. Use `shanone_execute_tool` to execute the tool with arguments
    ```
  </Tab>
</Tabs>

<Note>
For large integrations (Slack has 125 tools, Stripe has 328), relevance ranking may not surface every match — check `has_more`; if true, narrow the query or use `shanone_list_service_tools` instead.
</Note>

### shanone_get_tool_schema

Get the JSON Schema for a tool's input arguments.

<ParamField path="tool_name" type="string" required>
  The exact tool name (e.g. `"slack_post_message"`). Get this from `shanone_search_tools` or `shanone_list_service_tools`.
</ParamField>

<Tabs>
  <Tab title="Example Request">
    ```json
    { "tool_name": "slack_post_message" }
    ```
  </Tab>
  <Tab title="Example Response">
    ```
    **slack_post_message**

    Post a message to a Slack channel or user.

    **Input Schema:**
    ```json
    {
      "type": "object",
      "properties": {
        "channel": { "type": "string", "description": "Channel name or ID, e.g. #general" },
        "text": { "type": "string", "description": "Message text to post" }
      },
      "required": ["channel", "text"]
    }
    ```

    **Required arguments:** channel, text

    **Next step:** Use `shanone_execute_tool` with tool_name="slack_post_message" and the required arguments.
    ```
  </Tab>
</Tabs>

### shanone_execute_tool

Execute a specific tool with arguments. OAuth is handled automatically — if the tool needs a connection you haven't set up, you get a `connect_link` back instead of a hard error.

<ParamField path="tool_name" type="string" required>
  The exact tool name to execute.
</ParamField>
<ParamField path="arguments" type="string" required>
  Tool arguments as a **JSON string** (not a native object). Example: `'{"channel": "#general", "text": "Hello!"}'`. Pass `'{}'` for tools with no arguments.
</ParamField>
<ParamField path="session_id" type="string">
  Optional session ID for stateful/multi-step execution. Omit for a stateless call.
</ParamField>

<Tabs>
  <Tab title="Example Request">
    ```json
    {
      "tool_name": "slack_post_message",
      "arguments": "{\"channel\": \"#general\", \"text\": \"Hello from Cursor!\"}"
    }
    ```
  </Tab>
  <Tab title="Success">
    ```
    Tool: slack_post_message
    Duration: 412ms
    Session: tool_a1b2c3d4e5f6

    Result:
    { "ok": true, "message_ts": "1735282800.000100" }
    ```
  </Tab>
  <Tab title="Auth required">
    ```
    Authentication Required

    Tool: slack_post_message
    Service: slack
    Reason: auth_required
    Auth Type: oauth2

    Slack への接続が必要です。

    Connect Link: https://app.shanone.ai/connect/slack?request=req_abc123

    Please ask the user to visit the connect link to authenticate, then retry the request.
    ```
  </Tab>
  <Tab title="Confirmation required">
    ```
    Confirmation Required

    Tool: github_delete_repo
    Risk tier: destructive

    This action is irreversible. Please confirm you want to proceed.

    Ask the user to explicitly confirm this action. Once confirmed, call
    shanone_execute_tool again with the SAME arguments plus an additional
    "confirm": true field in the arguments JSON.
    ```
  </Tab>
</Tabs>

<Note>
When `reason` is `auth_required` or `auth_expired`, surface the `Connect Link` to the user. Once they authenticate, retry the exact same `shanone_execute_tool` call.
</Note>

## Skill Vendor

A **Skill** is a named, reusable prompt describing how to accomplish a task (`name` + `summary` + `instructions`). Skills are stored server-side, so they're reproducible across machines, IDEs, and agents, and also appear in Shanone's web dashboard under **Skills**.

**Recommended workflow:** `shanone_list_skills` before starting a task → `shanone_get_skill` to read it and follow its instructions yourself.

### shanone_list_skills

List saved Skills, newest first. Returns **all** Skills by default (paginated) — `query` is an optional filter, not a required search term.

<ParamField path="query" type="string">
  Optional filter matched against name/summary. Leave empty to return all Skills.
</ParamField>
<ParamField path="limit" type="integer" default="20">Maximum results per page (max 100).</ParamField>
<ParamField path="offset" type="integer" default="0">Number of results to skip.</ParamField>

<Tabs>
  <Tab title="Example Request">
    ```json
    { "query": "", "limit": 20, "offset": 0 }
    ```
  </Tab>
  <Tab title="Example Response">
    ```
    Showing 2 of 2 skill(s) (offset=0):

    - **Weekly Status Report** (skill_id: 3f1a9e2b-1234-4c56-9abc-1234567890ab)
      Gathers last week's closed issues and posts a summary to Slack #team.
    - **Daily Standup Reminder** (skill_id: 7c2b5f8d-5678-4d9e-bcde-234567890abc)
      Posts a standup reminder to Slack #general every weekday morning.

    **Next step:** Use `shanone_get_skill` with a skill_id to read the full instructions, then follow them.
    ```
  </Tab>
</Tabs>

## Permission Vendor

IAM-style tool/service access control. `shanone_list_services` is open to anyone; the other five require the caller to be a **Root** user, or an **SA2** user explicitly delegated the `tool-permissions:ManageOthers` policy action (delegated SA2 callers cannot target a Root user).

### shanone_list_services

List every registered service, with display names and tool counts. No special permission required.

<ParamField path="limit" type="integer" default="100">Max results per page (max 500).</ParamField>
<ParamField path="offset" type="integer" default="0">Results to skip.</ParamField>

<Tabs>
  <Tab title="Example Response">
    ```
    Showing 3 of 269 service(s) (offset=0):

    - **slack** (Slack) - 125 tool(s)
    - **github** (GitHub) - 176 tool(s)
    - **notion** (Notion) - 45 tool(s)

    More services available. Call again with offset=3.

    **Next steps:** Use a `service_name` above with `shanone_set_user_service_permission`,
    `shanone_list_user_tool_permissions`, or `shanone_batch_set_user_permissions`.
    ```
  </Tab>
</Tabs>

### shanone_batch_set_user_permissions

Enable/disable many services and/or tools for a target user in one call. Max 500 operations; individual failures don't abort the batch.

<ParamField path="target_user_id" type="string" required>The user_id to modify.</ParamField>
<ParamField path="operations" type="string" required>
  JSON array string of `{"type": "service"|"tool", "name": "...", "enabled": true|false}`.
</ParamField>

<Tabs>

    - service 'slack' -> enabled
    - service 'stripe' -> disabled

## Error Responses

| Situation | Response |
|-----------|----------|
| Unknown tool name | `Tool not found: <tool_name>` with a hint to use `shanone_search_tools` |
| Unknown `skill_id` | `Skill not found: <skill_id>` with a hint to use `shanone_list_skills` |
| Invalid JSON in `shanone_execute_tool`'s `arguments` | `Invalid JSON in arguments: ...` with the expected format |
| Integration needs OAuth and isn't connected | `reason: "auth_required"` (or `"auth_expired"`) plus a `connect_link` |
| High-risk action needs explicit confirmation | `reason: "confirmation_required"`; retry with `"confirm": true` |
| Caller lacks permission for a Permission Vendor tool | `Permission Denied` — caller must be Root, or SA2 delegated `tool-permissions:ManageOthers` |
| HTTP-level auth failure (bad/missing API key) | `401` with `error: "api_key_required"` or `"invalid_api_key"` |
| Missing/invalid organization ID (direct `/mcp` connection only) | `401 org_id_required` or `403 invalid_org_id` |
| Too many requests | `429` with `error: "rate_limit_exceeded"` and a `Retry-After` header |
