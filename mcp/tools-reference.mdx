Parameters, plan availability, billing, and usage accounting for the 29 Remote MCP tools.

This reference describes **Remote MCP over Streamable HTTP**. Local proxies differ by package and version; check your server’s `tools/list` for the actual tools and schemas.

Plan availability does not grant authorization: API-key scopes, user permissions, access to the target resource, and provider connections still apply.

“Billable” means consuming a Tool Call from your plan allowance, not necessarily an additional monetary charge. Administration and connection diagnostics are non-billable. All 13 skill tools require Plus or above and consume one Tool Call only on success.

Free users can discover skill names, descriptions, and input schemas. Execution is rejected with `PLAN_UPGRADE_REQUIRED` before accessing skill data. Signing in again does not resolve a plan restriction.

Results vary by tool: Markdown text, text containing JSON, or structured errors. Skill plan denials and operation failures use MCP `isError: true`. For execution tools, also inspect JSON fields such as `status`, `success`, and `reason`, plus the provider result.

Normal provider tools are generally billable on success and provider errors, with exceptions such as internal errors. Pre-execution rejection such as a missing account selection is not counted as execution usage. Connection checks record one non-billable parent call regardless of the number of accounts, and retain individual probe outcomes in the diagnostic result.

Unauthenticated requests, unknown MCP tools, and schema validation failures that do not reach execution are not counted as Tool Calls. Newly instrumented tools do not receive retroactive usage history.

## Health Check

### shanone_health_check

Check MCP connectivity, API-key authentication, and backend health. No provider credentials are tested.

No parameters. Pass `{}`.

## Tool Vendor

### shanone_search_tools

Search integration tools by keyword, ranked by relevance. Use list_service_tools when you need a complete service listing.

| Parameter | Type | Required / default | Description |
|---|---|---|---|
| `query` | string | Required | Search text; empty where optional. |

| `offset` | integer | `0` | Number of results to skip. |

## Connections

### shanone_list_connections

List saved connections visible to the caller. Stored configuration is not proof that authentication still works.

| Parameter | Type | Required / default | Description |
|---|---|---|---|
| `service` | string | `""` | Exact service identifier, such as gmail or slack. |

```json
{
  "service": "gmail"
}
```

Only IDs with `supports_account_selection: true` can be passed to execute_tool. Multiple-account selection currently supports Gmail. A `legacy:<service>` ID identifies a single connection for diagnostics; use it with check_connection, not execution account selection. Requires API-key scope `integrations:read` or `all`.

### shanone_check_connection

Verify saved connections using read-only provider APIs. Omitting service checks all connected services, with pagination.

| Parameter | Type | Required / default | Description |
|---|---|---|---|
| `service` | string | `""` | Exact service identifier, such as gmail or slack. |
| `connection_id` | string | `""` | Saved connection identifier. |
| `offset` | integer | `0` | Number of results to skip. |
| `limit` | integer | `10` | Maximum results per page. Maximum 20. |

```json
{
  "service": "gmail",
  "offset": 0,
  "limit": 10
}
```

Use connection_id to check one account. A page contains at most 20 connections, with three probes running concurrently and a 30-second timeout per probe. Requires `integrations:read` and `tasks:create`, or `all`, plus permission for the probe tool.

Results include `verified`, `reauth_required`, `insufficient_permissions`, `permission_denied`, `rate_limited`, `temporarily_unavailable`, `verification_failed`, `unsupported`, and `not_connected`. `verified` means the named read-only probe succeeded, not that every API operation or permission is available. Unsupported probes are not reported as successful.

## Execution

### shanone_execute_tool

Execute an integration tool. Inspect both the execution envelope and the provider result; completing a tool invocation does not by itself prove the provider operation succeeded.

| Parameter | Type | Required / default | Description |
|---|---|---|---|
| `tool_name` | string | Required | Exact tool name, such as gmail_get_profile. |
| `arguments` | string | Required | Integration tool arguments encoded as a JSON string; use "{}" for no arguments. |
| `session_id` | string | `""` | Optional legacy execution/session identifier. It does not select an OAuth account; omit for a stateless call. |
| `connection_id` | string | `""` | Required for Gmail execution. Use an ID whose supports_account_selection is true. |
| `request_id` | string | `""` | Optional retry identifier. Reuse only for the same request, arguments, and account; do not reuse for a different operation. |

```json
{
  "tool_name": "gmail_get_profile",
  "arguments": "{}",
  "connection_id": "conn_example"
}
```

For Gmail, obtain an account ID with list_connections and provide it on each call. Omitting it returns `CONNECTION_SELECTION_REQUIRED`. To use another account, change the ID on the next call. `execution_context_id` is no longer supported.

For `auth_required` / `auth_expired`, follow the returned connection instructions. For `confirmation_required`, obtain confirmation and retry with `"confirm": true` in the same arguments. Usage is recorded under the executed tool’s name, without an additional execute_tool charge or count.

## Parameter Policies

### shanone_get_tool_parameter_policy

Read the argument constraints configured for a target user’s tool. Tool access and allowed argument values are separate controls.

| Parameter | Type | Required / default | Description |
|---|---|---|---|
| `target_user_id` | string | Required | User whose permissions are being inspected or changed. |
| `tool_name` | string | Required | Exact tool name, such as gmail_get_profile. |

### shanone_set_tool_parameter_policy

Set or replace one field’s argument policy. Constraints are applied by the server during execution.

| Parameter | Type | Required / default | Description |
|---|---|---|---|
| `target_user_id` | string | Required | User whose permissions are being inspected or changed. |
| `tool_name` | string | Required | Exact tool name, such as gmail_get_profile. |
| `field_name` | string | Required | Exact input parameter name to constrain. |
| `policy_type` | string | Required | One of the policy types listed below. |
| `policy_value` | string | `"{}"` | Policy configuration as a JSON object string; see the policy table below. |

```json
{
  "target_user_id": "user_example",
  "tool_name": "gmail_send_message",
  "field_name": "to",
  "policy_type": "domain_allowlist",
  "policy_value": "{\"values\":[\"example.com\"]}"
}
```

| policy_type | Example policy_value contents (encode as a JSON string) | Meaning |
|---|---|---|
| `allowlist / denylist` | `{"values":["a","b"]}` | Allow / reject listed values. |
| `domain_allowlist` | `{"values":["example.com"]}` | Restrict domains. |
| `pattern` | `{"value":"^[A-Z].*"}` | Require a regex match. |
| `range` | `{"min":0,"max":100}` | Bound a numeric value. |
| `max_length / max_items` | `{"value":200}` | Limit length / item count. |
| `forced_value` | `{"value":"audit@example.com"}` | Always replace the value. |
| `forced_append` | `{"value":"audit@example.com"}` | Append the configured value. |
| `default_value` | `{"value":"user"}` | Fill only when omitted. |
| `required_override` | `{}` | Require the field. |

### shanone_delete_tool_parameter_policy

Remove the policy on one field. This does not change the tool’s allow/deny permission.

| Parameter | Type | Required / default | Description |
|---|---|---|---|
| `target_user_id` | string | Required | User whose permissions are being inspected or changed. |
| `tool_name` | string | Required | Exact tool name, such as gmail_get_profile. |
| `field_name` | string | Required | Exact input parameter name to constrain. |

## Errors and migration

| Result | Action |
|---|---|
| `PLAN_UPGRADE_REQUIRED` | Upgrade to Plus or above. Denied calls are non-billable. |
| `TOOL_CALL_LIMIT_EXCEEDED` | Check the plan allowance. The skill operation is not executed or billed. |
| `SUBSCRIPTION_UNAVAILABLE` | Subscription data could not be verified. Retry later. |
| `CONNECTION_SELECTION_REQUIRED` | Provide a Gmail ID returned by list_connections. |
| `CONNECTION_NOT_FOUND` / `connection_not_found` | Check connection ownership and existence. Another account is not selected automatically. |
| `401` / `403` | Check your API key, organization ID, and permissions. Distinguish transport errors from MCP plan denials. |

`shanone_create_execution_context`, `shanone_get_execution_context`, and `shanone_switch_connection` have been removed. Refresh the client’s tool list and migrate to explicit connection IDs.

`shanone_get_tool_usage` is a design proposal, not an available tool.
