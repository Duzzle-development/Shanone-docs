The Shanone MCP Server gives any MCP-compatible client — Cursor, Claude Code, Codex, and others — programmatic access to Shanone's integration ecosystem, Skill library, and (for admins) permission controls, without exposing hundreds of individual integration actions to your agent's context window.

## Available Tools

Shanone exposes **18 tools**, organized into four groups:

### Health Check (1 tool)

| Tool | Description |
|------|-------------|
| `shanone_health_check` | Verify connectivity, API key validity, and backend health. Returns a plain-text status screen. |

### Tool Vendor (4 tools)

| Tool | Description |
|------|-------------|
| `shanone_search_tools` | Search the integration catalog by keyword (relevance-ranked) |
| `shanone_list_service_tools` | List every tool for one service, in name order (for full enumeration) |
| `shanone_get_tool_schema` | Get a tool's input JSON Schema |
| `shanone_execute_tool` | Execute a tool with arguments; returns a `connect_link` if OAuth is needed |

### Skill Vendor (5 tools)

| Tool | Description |
|------|-------------|
| `shanone_list_skills` | List saved Skills (metadata only), newest first |
| `shanone_get_skill` | Get a Skill's full instructions |
| `shanone_create_skill` | Save a new reusable Skill |
| `shanone_update_skill` | Update an existing Skill's name/summary/instructions |
| `shanone_delete_skill` | Permanently delete a Skill |

### Permission Vendor (6 tools — Root / delegated SA2 only, except the first)

| Tool | Description |
|------|-------------|
| `shanone_list_services` | List every registered service, with tool counts (no special permission required) |
| `shanone_list_user_tool_permissions` | List a target user's permission overrides |
| `shanone_set_user_tool_permission` | Enable/disable one specific tool for a target user |
| `shanone_set_user_service_permission` | Enable/disable all tools of a service for a target user |
| `shanone_get_permission_summary` | Aggregated counts of a target user's enabled/disabled access |
| `shanone_batch_set_user_permissions` | Apply up to 500 service/tool operations for a target user at once |

<Note>
For full parameters, response formats, and examples for every tool, see the [Tools Reference](/mcp/tools-reference).
</Note>

## Authentication

The Shanone MCP Server requires an API key. Get one from **Settings → API Keys** in the Shanone dashboard — it's shown once, in the form `sh_xxxxxxxxxxxxxxxx`.

Send it as `Authorization: Bearer <api_key>` (or `X-API-Key: <api_key>`) with every request. If you connect directly to the remote endpoint (rather than through the local stdio proxy), you also need your organization ID as `X-Org-Id` — see [Setup](/mcp/setup) for exact client configuration.

<Warning>
Keep your API key secure. Do not commit it to version control or share it publicly.
</Warning>

## Recommended Workflows

### Tool Vendor: search → schema → execute

<Steps>
  <Step title="Search for a tool">
    Call `shanone_search_tools` with a task-shaped natural-language query (optionally filtered by `service`).
  </Step>
  <Step title="Inspect its schema (if needed)">
    Call `shanone_get_tool_schema` with the exact tool name to see required and optional arguments.
  </Step>
  <Step title="Execute it">
    Call `shanone_execute_tool` with the tool name and a JSON string of arguments. If the underlying service requires authentication you haven't set up, the response includes a `connect_link` — visit it, then retry.
  </Step>
</Steps>

### Skill Vendor: list → get → follow → save

<Steps>
  <Step title="Check for an existing Skill">
    Call `shanone_list_skills` before starting a task — it returns all your saved Skills (optionally filtered by `query`), paginated.
  </Step>
  <Step title="Read its instructions">
    Call `shanone_get_skill` with a `skill_id` to get the full step-by-step instructions.
  </Step>
  <Step title="Follow the instructions">
    Your agent executes the steps itself, using `shanone_search_tools` / `shanone_execute_tool` for any integration actions along the way.
  </Step>
  <Step title="Save new workflows">
    Once you've built a workflow worth reusing, call `shanone_create_skill` so it's available from any machine or agent later.
  </Step>
</Steps>

### Permission Vendor: for team administrators

<Steps>
  <Step title="Look up service names">
    Call `shanone_list_services` (no special role required) to get exact `service_name` values.
  </Step>
  <Step title="Apply overrides">
    Call `shanone_set_user_service_permission` / `shanone_set_user_tool_permission` for one change, or `shanone_batch_set_user_permissions` for many at once.
  </Step>
  <Step title="Verify">
    Call `shanone_get_permission_summary` for the same user to confirm the change landed as intended.
  </Step>
</Steps>

## Use Cases

### Discover and use an integration from your IDE

```
"Post 'Deploy finished' to Slack #general"
"Create a GitHub issue titled 'Fix login redirect bug' in owner/repo"
"Search for tools related to Notion"
```

Your agent will call `shanone_search_tools`, then `shanone_execute_tool` (fetching the schema first if it's unsure of the arguments).

### Handle authentication mid-task

```
"Send a message to my team on Slack"
```

If Slack isn't connected yet, `shanone_execute_tool` returns `success: false` with `reason: "auth_required"` and a `connect_link`. Your agent should surface that link, wait for you to authenticate, then retry the same call.

### Save and reuse a workflow as a Skill

```
"Save this as a skill called 'Weekly Status Report'"
"List my saved skills"
"Run my 'Weekly Status Report' skill"
```

Skills created this way also appear in Shanone's web dashboard under **Skills**.
