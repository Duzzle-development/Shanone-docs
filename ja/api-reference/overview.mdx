## Shanoneにプログラムからアクセスする2つの方法

ほとんどのエージェント連携には[MCPサーバー](/ja/mcp/overview)を使うべきです——Cursor、Claude Code、その他のMCPクライアントはこれをネイティブに話します。ここで解説するREST APIは、その裏側にある機能そのものであり、MCPクライアントを介さずにスクリプト・バックエンドサービス・CIジョブから直接Shanoneを呼び出したい場合に便利です。実際、Shanone自身のローカルstdio MCPプロキシ(`@duzzle/shanone-mcp`とそのPython版)も、このREST APIをごく薄くラップしただけの実装になっています。

## ベースURL

```
https://app.shanone.ai/api
```

## 認証

外部からのAPIリクエスト(WebダッシュボードのセッションベースのJWT認証とは異なります)は、ShanoneのAPIキーを使って認証します。

```bash
curl "https://app.shanone.ai/api/v1/tools/search?query=post+slack+message" \
  -H "Authorization: Bearer sh_xxxxxxxxxxxxxxxx"
```

キーの管理、スコープ設定、レート制限については[認証](/ja/api-reference/authentication)を参照してください。

    `GET /v1/health` — `shanone_health_check`の裏側にある、同じチェック
  </Card>

これらは同じ形をしたMCPメタツールに直接対応しています——`GET /v1/tools/search`は`shanone_search_tools`が内部で呼び出しているエンドポイントであり、`POST /v1/tools/{tool_name}/execute`は`shanone_execute_tool`に対応します。すでに使いたいMCPツールがわかっている場合、REST側のエンドポイントもほぼ同じ動詞を、少し形の違うURLに向けて使うだけです。

<Note>
Shanoneのダッシュボード(Settings、API Keys、Webhooks、Integrationsなど)は、はるかに大規模なJWT認証の内部ルート群によって支えられています——これらは外部APIの一部ではなく、APIキーで直接呼び出すことを意図したものではありません。
</Note>

## 例: 検索してから実行する

<Tabs>
  <Tab title="cURL">
    ```bash
    # 1. 検索
    curl "https://app.shanone.ai/api/v1/tools/search?query=post+slack+message&limit=5" \
      -H "Authorization: Bearer sh_xxxxxxxxxxxxxxxx"

    # 2. 実行
    curl -X POST "https://app.shanone.ai/api/v1/tools/slack_post_message/execute" \
      -H "Authorization: Bearer sh_xxxxxxxxxxxxxxxx" \
      -H "Content-Type: application/json" \
      -d '{"arguments": {"channel": "#general", "text": "Hello from the API!"}}'
    ```
  </Tab>
  <Tab title="Python">
    ```python
    import requests

    headers = {"Authorization": "Bearer sh_xxxxxxxxxxxxxxxx"}
    base = "https://app.shanone.ai/api"

    search = requests.get(f"{base}/v1/tools/search",
                          params={"query": "post slack message", "limit": 5},
                          headers=headers).json()

    result = requests.post(f"{base}/v1/tools/slack_post_message/execute",
                            json={"arguments": {"channel": "#general", "text": "Hello from the API!"}},
                            headers=headers).json()
    ```
  </Tab>
</Tabs>

## レスポンスの形式

ToolベンダーとSkillベンダーのRESTエンドポイントはJSONオブジェクトを返します。更新後のMCP検索もJSONテキストを返します。検索レスポンスの構造例（値とスキーマは説明用に簡略化）:

```json
{
  "tools": [
    {
      "name": "linear_list_teams",
      "service": "linear",
      "description": "List all teams in the Linear workspace.",
      "inputSchema": {
        "type": "object",
        "properties": {},
        "required": []
      }
    }
  ],
  "total": 1,
  "query": "list teams",
  "service": "linear",
  "offset": 0,
  "limit": 5,
  "has_more": false,
  "next_step": "Use shanone_execute_tool with an arguments object when inputSchema is present; otherwise fetch the schema."
}
```

`GET /v1/tools/search` は `schema_limit`（既定3、0〜5）で上位候補のスキーマを同梱します。合計24,000 UTF-8バイトを超える場合などは `inputSchema` の代わりに `schemaRef` を返します。詳しくは[MCP検索リファレンス](/ja/mcp/tools-reference#shanone_search_tools)を参照してください。

実行結果の外側の形式はREST・MCPの実装によって異なります。`status`、`success`、`reason`などの外側の結果と、外部サービスの結果を確認してください。

## レート制限

| 設定項目 | デフォルト値 |
|---------|---------|
| 1分あたりのリクエスト数 | 60 |
| 1日あたりのリクエスト数 | 10,000 |

いずれもAPIキーごとに**Settings → API Keys**から設定変更でき(最大1,000/分、1,000,000/日まで)、どちらかを超えると`Retry-After`ヘッダー付きで`429`が返されます。
