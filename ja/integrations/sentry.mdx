# Sentry

ShanoneのSentry連携は、issueのトリアージ、パフォーマンストレーシング、セッションリプレイ、リリースヘルス、組織管理(メンバー、SCIM、連携アプリ)にまたがる115個のツールをエージェントに提供します——日常的なSentry運用の大半をエージェントから離れずに行えます。

## はじめに

<Steps>
  <Step title="Sentry Auth Tokenを作成する">
    Sentryの**Settings → Developer Settings**で、必要なスコープ(例: `project:read`、`event:read`、`org:read`)を持つInternal IntegrationまたはPersonal Auth Tokenを作成します。
  </Step>
  <Step title="ShanoneでAPIキーを接続する">
    エージェントにSentry関連の作業を依頼(例: 「プロジェクトの未解決issueを一覧表示して」)するか、Shanoneダッシュボードの**連携**からAuth Tokenを事前に登録しておきます。Organization Slugを設定しておくと、呼び出しごとに指定する必要がなくなります。
  </Step>
  <Step title="リクエストを再実行する">
    接続が完了すると、`sentry_*`ツールに対する`shanone_execute_tool`呼び出しが成功するようになります。
  </Step>
</Steps>

## トラブルシューティング

<AccordionGroup>
  <Accordion title="トークンが有効なはずなのに401/403エラーになる">
    Auth Tokenのスコープはエンドポイントごとに一致している必要があります——例えば`sentry_bulk_update_issues`には`event:write`が必要ですが、`sentry_list_projects`には`project:read`のみで十分です。**Settings → Developer Settings**で不足しているスコープを追加してトークンを再生成してください。
  </Accordion>
  <Accordion title="issueがあるはずのプロジェクトでsentry_list_issuesが空になる">
    多くの一覧系ツールはデフォルトで短い期間(Sentryの`statsPeriod`)かつ未解決issueのみを対象にしています。明示的に`query`/`statsPeriod`を指定してください——正確なパラメータ名は`sentry_list_issues`の`shanone_get_tool_schema`で確認できます。
  </Accordion>
  <Accordion title="呼び出しごとにOrganization Slugのエラーが出る">
    接続時に設定していない場合、多くのツールは呼び出しごとに明示的な`organization_slug`引数を要求します——連携アプリ側で一度設定しておけば、毎回指定する必要がなくなります。
  </Accordion>
  <Accordion title="sentry_trigger_issue_autofixがすぐに結果を返さない">
    Seer autofixは非同期で実行されます。実行状態が完了するまで、同じissueに対して`sentry_get_issue_autofix`をポーリングしてください。
  </Accordion>
</AccordionGroup>
