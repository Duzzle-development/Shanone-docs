# Slack

ShanoneのSlack連携では、日常的なメッセージングからチャンネル管理、Canvas、Lists、Enterprise Gridの管理操作まで、125のツールをエージェントが利用できるようになります。

## はじめに

<Steps>
  <Step title="OAuthで接続する">
    エージェントにSlackで何か作業をしてもらう(例:「#generalに投稿して」)か、Shanoneダッシュボードの**Integrations**から事前に接続します。どちらの方法でも、ShanoneのSlackアプリをワークスペースに対して認可するための`connect_link`が発行されます。
  </Step>
  <Step title="プライベートチャンネルにアプリを招待する">
    Botトークンによる操作(投稿、履歴の取得など)は、Slackアプリが追加されているチャンネルでのみ動作します。パブリックチャンネルでは通常これは不要ですが、プライベートチャンネルではSlack上で明示的にアプリを招待する必要があります。
  </Step>
  <Step title="リクエストを再試行する">
    接続が完了したら、もう一度エージェントに依頼してください——`shanone_execute_tool`は`connect_link`を返す代わりに成功するようになります。
  </Step>
</Steps>

<Note>
リマインダー・スター・検索・DND設定などの一部ツールは、Botトークンではなく同じOAuthフローで取得されるSlackの**ユーザートークン**を使用します。他の機能は動くのにこれらのツールだけ失敗する場合は、OAuth接続をやり直して両方のトークンが付与されているか確認してください。詳しくは[Bot名義とユーザー名義の切り替え](#bot名義とユーザー名義の切り替え)を参照してください。
</Note>

## Bot名義とユーザー名義の切り替え

SlackのOAuthでは、**Botトークン**(`xoxb-`)と**ユーザートークン**(`xoxp-`)の2種類が発行されます。Shanoneはどちらも保存しており、ツールごとに`act_as`パラメータで送り手を切り替えられます。

| `act_as` | 使われるトークン | Slack上での見え方 |
|----------|-----------------|------------------|
| `"bot"`(既定) | Botトークン `xoxb-` | **Shanone**アプリからの投稿として表示される |
| `"user"` | ユーザートークン `xoxp-` | **あなた本人**の投稿として表示される |

`act_as`を省略した場合はこれまでと同じくBot名義で動作するため、既存の使い方に影響はありません。

### 使い分け

<CardGroup cols={2}>
  <Card title="Bot名義が向いているケース" icon="robot">
    自動レポートの配信、CI/CDの通知、定期的なリマインドなど。**自動化された処理であることが明示される**ため、チームにとって分かりやすくなります。
  </Card>
  <Card title="ユーザー名義が向いているケース" icon="user">
    同僚へのDM返信、自分の代理での発言など。**本人の発言として自然に見せたい**場合や、Botが参加していないチャンネルの履歴を読みたい場合に使います。
  </Card>
</CardGroup>

### 使用例

同じ`slack_post_message`でも、`act_as`だけで送り手が変わります。

```json
// Shanoneアプリからの投稿として表示される(既定)
{
  "tool_name": "slack_post_message",
  "arguments": {
    "channel": "#general",
    "text": "デプロイが完了しました"
  }
}
```

```json
// あなた本人の投稿として表示される
{
  "tool_name": "slack_post_message",
  "arguments": {
    "channel": "#general",
    "text": "確認しました、ありがとうございます",
    "act_as": "user"
  }
}
```

エージェントに対して「**私名義で**送って」「**Botとして**通知して」と自然言語で伝えるだけでも、エージェントが`act_as`を適切に指定します。

### `act_as`を指定できないツール

Slackの仕様上、片方のトークンでしか動作しないツールがあります。これらは`act_as`を指定しても**自動的に正しいトークンが選択される**ため、エラーにはなりません。

  </Accordion>

<Warning>
**Bot名義で投稿できるのはBotが参加できる場所だけです。** 人間同士の1対1のDMはメンバーが2人で固定されており、Botを含む第三者は参加できません。そのようなDMへ`act_as="bot"`で投稿しようとすると`channel_not_found`が返ります。他の人とのDMには`act_as="user"`を使ってください。
</Warning>

### 既定値を固定する

毎回`act_as`を指定するのが面倒な場合は、**パラメータポリシー**でツールごとの既定値を設定できます。`default_value`ポリシーを使うと、エージェントが`act_as`を省略したときだけその値が適用され、明示的に指定された場合はそちらが尊重されます。

たとえば`slack_post_message`の`act_as`に`default_value: "user"`を設定すると、以降の投稿は既定で本人名義になります。

<Note>
常に強制したい場合は`forced_value`ポリシーを使ってください。この場合はエージェントの指定を無視して必ずその値が使われます。
</Note>

## トラブルシューティング

<AccordionGroup>
  <Accordion title="プライベートチャンネルに投稿できない">
    Botトークンによるツールがプライベートチャンネルに投稿できるようにするには、Slackアプリがそのチャンネルのメンバーである必要があります。Slack上でアプリを招待してから再試行してください。
  </Accordion>
  
  <Accordion title="メッセージ検索が動作しない">
    `slack_search_messages` / `slack_search_all` / `slack_search_files`にはOAuthの**ユーザートークン**が必要で、Botトークンだけでは動作しません。**Integrations**からSlackを再接続し、両方のトークンが付与されているか確認してください。
  </Accordion>

  <Accordion title="投稿がBotからになってしまう / 本人名義にしたい">
    `act_as`を省略すると既定でBot名義になります。本人の投稿として表示したい場合は`act_as="user"`を指定してください(詳細は[Bot名義とユーザー名義の切り替え](#bot名義とユーザー名義の切り替え))。毎回指定したくない場合は、パラメータポリシーの`default_value`で既定値を`user`に変更できます。
  </Accordion>

  <Accordion title="他の人とのDMに投稿すると channel_not_found になる">
    人間同士の1対1のDMはメンバーが2人で固定されており、Botは参加できません。`act_as="user"`を指定して本人名義で投稿してください。Bot名義で送れるのは、Bot自身とのDM・Botを招待済みのチャンネル・Botを含むグループDMだけです。
  </Accordion>

  <Accordion title="連携後もツールが権限エラーになる">
    ツールが必要とするスコープが、現在の連携に含まれていない可能性があります。Shanoneのアップデートで新しいスコープが追加された場合、**Integrations**からSlackを再連携すると解消します。BotトークンとユーザートークンではSlackが要求するスコープ名が異なるため、片方の名義でだけ失敗することもあります。
  </Accordion>
  
  <Accordion title="チャンネルが見つからない">
    まず`slack_list_channels`を呼び出して、利用可能なすべてのチャンネルとそのIDを確認してください。プライベートチャンネルはアプリがメンバーである場合のみ表示されます。
  </Accordion>
  
  <Accordion title="ファイルのアップロードに失敗する">
    ファイルパス/URLにアクセスできること、対象チャンネルへのアクセス権限がアプリにあること(上記参照)を確認してください。
  </Accordion>
  
  <Accordion title="予約メッセージの送信に失敗する">
    予約時刻が少なくとも数秒後の未来であり、Slack自体の予約可能な範囲内であること、またタイムスタンプの形式が`slack_schedule_message`のスキーマで期待される形式と一致していることを確認してください(`shanone_get_tool_schema`で確認できます)。
  </Accordion>
</AccordionGroup>
