description: "Cursor、Claude Code、CodexでShanone MCPサーバーを設定する——ローカルstdioプロキシ経由(推奨)、またはリモートHTTPへの直接接続。"
---

Shanoneには2つの接続方法があります。ほとんどのクライアントは**ローカルstdioプロキシ**を使うべきです——設定が簡単で、必要なのはAPIキーだけです。カスタムHTTPヘッダーをうまく扱えるクライアント(Cursorなど)であれば、代わりにShanoneのリモートエンドポイントに**直接**接続することもできます。この場合ローカルプロセスを動かす必要はありません。

| | ローカルstdioプロキシ | リモートHTTP直接接続 |
|---|---|---|
| パッケージ/URL | `@duzzle/shanone-mcp`(npm) | `https://app.shanone.ai/mcp` |
| ローカルにNode.jsが必要か | 必要(18以上) | 不要 |
| 必要な認証 | APIキーのみ | APIキー**と**組織ID |
| 向いている用途 | ほとんどのクライアント、最も簡単な設定 | カスタムヘッダーの送信に対応したクライアント |

## 前提条件

- サポート対象クライアントのいずれか: **Cursor**、**Claude Code**、または**Codex**
- Shanoneアカウントと、**Settings → API Keys**から取得したAPIキー(`sh_`で始まります)
- ローカルプロキシを使う場合はNode.js 18以上

## ステップ1: APIキーを取得する

<Steps>
  <Step title="サインインする">
    [app.shanone.ai](https://app.shanone.ai)にアクセスしてサインインします。
  </Step>
  <Step title="API Keysを開く">
    **Settings → API Keys**に移動します。
  </Step>
  <Step title="キーを作成する">
    **Create API Key**をクリックし、名前を付けて、平文の値をコピーします——`sh_xxxxxxxxxxxxxxxx`という形式で、1度だけ表示されます。
  </Step>
</Steps>

<Warning>
APIキーはパスワードと同じように扱ってください。バージョン管理にコミットしたり、公開して共有したりしないでください。
</Warning>

## ステップ2: クライアントを設定する

<Tabs>
  <Tab title="Cursor (local proxy)">
    `~/.cursor/mcp.json`を編集します(または**Cursor Settings → MCP**からサーバーを追加します)。

    ```json
    {
      "mcpServers": {
        "shanone": {
          "command": "npx",
          "args": ["-y", "@duzzle/shanone-mcp"],
          "env": {
            "SHANONE_API_KEY": "sh_xxxxxxxxxxxxxxxx"
          }
        }
      }
    }
    ```

    MCPサーバーを読み込むため、Cursorを再起動してください。
  </Tab>
  <Tab title="Cursor (direct HTTP)">
    ```json
    {
      "mcpServers": {
        "shanone": {
          "url": "https://app.shanone.ai/mcp",
          "headers": {
            "Authorization": "Bearer sh_xxxxxxxxxxxxxxxx",
            "X-Org-Id": "org_xxxxxxxxxxxxxxxx"
          }
        }
      }
    }
    ```

    組織IDは、APIキーと同じ**Settings → API Keys**ページで確認できます。
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add shanone \
      --env SHANONE_API_KEY=sh_xxxxxxxxxxxxxxxx \
      -- npx -y @duzzle/shanone-mcp
    ```

    または、プロジェクト内の`.mcp.json`を編集します。

    ```json
    {
      "mcpServers": {
        "shanone": {
          "command": "npx",
          "args": ["-y", "@duzzle/shanone-mcp"],
          "env": {
            "SHANONE_API_KEY": "sh_xxxxxxxxxxxxxxxx"
          }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Codex">
    `~/.codex/config.toml`を編集します。

    ```toml
    [mcp_servers.shanone]
    command = "npx"
    args = ["-y", "@duzzle/shanone-mcp"]

    [mcp_servers.shanone.env]
    SHANONE_API_KEY = "sh_xxxxxxxxxxxxxxxx"
    ```
  </Tab>
</Tabs>

<Warning>
上記のプレースホルダーのキー/組織IDは、すべて実際の値に置き換えてください。
</Warning>

## Pythonプロキシ(代替手段)

Python中心の環境向けに、Pythonパッケージも用意されています。

```bash
pip install shanone-mcp
```

```json
{
  "mcpServers": {
    "shanone": {
      "command": "shanone-mcp",
      "env": {
        "SHANONE_API_KEY": "sh_xxxxxxxxxxxxxxxx"
      }
    }
  }
}
```

## 接続を確認する

<Steps>
  <Step title="クライアントのAIチャットを開く">
    MCPに接続されたチャットインターフェースであれば何でも構いません。
  </Step>
  <Step title="ヘルスチェックを依頼する">
    「Shanoneの接続状態を確認して」と伝えます。
  </Step>
  <Step title="結果を確認する">
    `shanone_health_check`が、APIキーが有効でデータベースに到達可能な、健全なステータスを報告するはずです。
  </Step>
</Steps>

## 設定リファレンス

| 設定項目 | 値 |
|---------|-------|
| ローカルプロキシパッケージ | `@duzzle/shanone-mcp`(npm)、環境変数`SHANONE_API_KEY`が必要、Node.js 18以上 |
| リモート直接接続URL | `https://app.shanone.ai/mcp`(Streamable HTTP) |
| 認証ヘッダー(両方式共通) | `Authorization: Bearer <api_key>`(`X-API-Key`も可) |
| 追加ヘッダー(直接接続のみ) | `X-Org-Id: <org_id>`(または`?org_id=`クエリパラメータでも可) |

## トラブルシューティング

<AccordionGroup>
  <Accordion title="401 api_key_required">
    APIキーが送信されていません。設定の`env`/`headers`ブロックが、上記の内容と正確に一致しているか確認してください。
  </Accordion>
  <Accordion title="401 invalid_api_key">
    キーが欠落している、不正な形式である、または無効化されています。**Settings → API Keys**から新しいキーを生成してください。
  </Accordion>
  <Accordion title="401 org_id_required / 403 invalid_org_id (direct HTTP only)">
    `X-Org-Id`を指定せずに(あるいは誤った値で)、直接`/mcp`エンドポイントを使用しています。**Settings → API Keys**から正確な組織IDをコピーするか、この設定が不要なローカルプロキシに切り替えてください。
  </Accordion>
  <Accordion title="429 rate_limit_exceeded">
    キーのレート制限を超えました。`Retry-After`ヘッダーに示された時間だけ待つか、管理者に制限の緩和を依頼してください。
  </Accordion>
  <Accordion title="Tools not appearing">
    1. 設定を編集した後、クライアントを完全に再起動してください。
    2. JSON/TOMLの構文エラーがないか確認してください。
    3. 設定内のサーバー名が、参照している名前(通常は`shanone`)と一致しているか確認してください。
    4. ローカルプロキシを使用している場合は、ターミナルで直接`npx -y @duzzle/shanone-mcp`を実行して、起動時のエラーを確認してください。
  </Accordion>
</AccordionGroup>

## セキュリティのベストプラクティス

<Steps>
  <Step title="環境変数を使う">
    クライアントが対応している場合は、キーをコミットする設定ファイルに直接書き込む代わりに、環境変数を参照してください。
  </Step>
  <Step title="マシン/エージェントごとにキーに名前を付ける">
    そうすることで、1つを無効化しても他に影響が及びません。
  </Step>
  <Step title="定期的にローテーションする">
    **Settings → API Keys**から新しいキーを作成し、古いキーを無効化してください。
  </Step>
</Steps>
