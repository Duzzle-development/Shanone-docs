## MCPとは何か

**Model Context Protocol (MCP)** は、AIアプリケーションを外部のツールやデータソースに接続するためのオープンスタンダードです。互換性のあるクライアント(Cursor、Claude Code、Codexなど)が、ペアごとに専用の統合コードを書かなくても互換性のあるサーバーと話せるようにする、標準化された「ポート」のようなものだと考えてください。

Shanoneは*それ自体が*MCPサーバーです。一度接続すれば、どのMCPクライアントもShanoneの連携カタログ、Skillライブラリ、そして(管理者であれば)権限管理ツールにプログラムからアクセスできるようになります。

## なぜアクションごとに1ツールではなく、メタツールパターンなのか

Shanoneのバックエンドは269以上のサービス統合を実装しており、それぞれが数十から数百の個別アクションを持っています(Stripeだけで328個)。すべてのアクションを個別のMCPツールとして登録すると、エージェントが動き出す前にコンテキストウィンドウが溢れてしまいます。そこでShanoneは、Composioのカタログ構成に近い**Tool Vendor**パターンを採用し、カタログ全体に対してオンデマンドで検索・確認・実行を行う、小さく固定された一連のメタツールを公開しています。

再利用可能な保存済みワークフローについては、並行する**Skill Vendor**パターン(`shanone_list_skills` → `shanone_get_skill`)が同じ役割を果たします。また、**Permission Vendor**というツール群により、RootまたはSA2委任管理者が誰が何を使えるかを管理できます。

## サーバーアーキテクチャ

Shanoneは実際には、同じツールセットを共有しつつ両方がMCPで話す、2つのものを提供しています。

| コンポーネント | トランスポート | 内容 |
|-----------|-----------|-----------|
| **リモートMCPサーバー** | `/mcp`でのStreamable HTTP | Shanoneのバックエンドプロセス自体の内部で動作します。`src.services.tool_vendor`を直接呼び出すため、余分なネットワークホップがありません。これが[セットアップ](/ja/mcp/setup)の`X-Org-Id`で保護された直接接続が話す相手です。 |
| **ローカルstdioプロキシ**(npmパッケージ`@duzzle/shanone-mcp`、またはPython版の`apps/mcp-server`パッケージ) | stdio | あなたのマシン上で動作し、各MCPツール呼び出しを、あなたのAPIキーを使ってHTTPS経由でShanoneのREST API(`/api/v1/tools/...`、`/api/v1/skills/...`、`/api/v1/permissions/...`)に転送します。カスタムHTTPヘッダーに対応していないクライアントにとって、最も簡単な選択肢です。 |

どちらも同じ名前・同じパラメータで同じメタツールを公開しています——お使いのクライアントがより良くサポートしている方のトランスポートを選んでください。正確な設定については[セットアップ](/ja/mcp/setup)を参照してください。

## 認証

すべてのリクエスト——直接のHTTPエンドポイント経由であっても、ローカルプロキシ経由であっても——は、あなたのShanone APIキーで認証されます。

```
Authorization: Bearer sh_xxxxxxxxxxxxxxxx
```

(`X-API-Key: sh_xxx`も使用可能です。)**直接リモートエンドポイント**では、追加でお使いの組織ID(organization ID)を第2の複合要素として要求します——`X-Org-Id`ヘッダーまたは`?org_id=`クエリパラメータとして送信します——これにより、APIキーだけが漏洩してもツールを呼び出すことはできません。ローカルstdioプロキシではこの第2要素は不要で、APIキーのみが必要です。レート制限を含めた全体像については[認証](/api-reference/authentication)を参照してください。
