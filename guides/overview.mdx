## What these guides assume

You've already got Shanone connected to at least one MCP client (Cursor, Claude Code, etc.) — if not, start with the [Quickstart](/quickstart). Everything below is about how to *use* Shanone effectively once it's wired up, not how to wire it up in the first place.

## The mental model

Shanone doesn't hand your agent a giant static list of tools. It hands it a handful of **meta-tools** that search a live catalog of 269+ integrations and execute whichever one turns out to be relevant:

| Meta-tool | Purpose |
|-----------|---------|
| `shanone_search_tools` | Find the right tool by describing the task, not the tool name |
| `shanone_list_service_tools` | Enumerate every tool for one service (for "what can I do with X" questions) |
| `shanone_get_tool_schema` | See exactly what arguments a tool expects before calling it |
| `shanone_execute_tool` | Actually run it, with OAuth handled automatically via `connect_link` |
| `shanone_list_skills` / `shanone_get_skill` | Check for and read a saved, reusable workflow before reinventing it |

Most of the guidance in [Best Practices](/guides/best-practices) is really about giving your agent enough signal to pick the right tool on the first `shanone_search_tools` call, instead of guessing and retrying.
