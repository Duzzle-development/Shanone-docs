# Databricks

Shanone's Databricks integration gives your agent 155 tools spanning SQL execution, cluster/job/pipeline management, Unity Catalog administration, MLflow experiments, model serving, secrets, and workspace files.

## Getting Started

<Steps>
  <Step title="Connect via OAuth">
    Ask your agent to do something with Databricks (e.g. "list my SQL warehouses"), or connect proactively from **Integrations** in the Shanone dashboard. You'll be asked for your workspace URL (e.g. `https://adb-1234567890123456.7.azuredatabricks.net`) and then get a `connect_link` to authorize Shanone.
  </Step>
  <Step title="Authorize the workspace">
    Approve Databricks' OAuth consent screen for the specific workspace you entered — Databricks credentials are workspace-scoped, so reconnect separately for each workspace you want Shanone to act on.
  </Step>
  <Step title="Retry your request">
    Once connected, `shanone_execute_tool` calls for `databricks_*` tools will succeed.
  </Step>
</Steps>

## Troubleshooting

<AccordionGroup>
  <Accordion title="All tools fail with a connection error after working before">
    Databricks OAuth tokens are workspace-scoped and expire; if a long-idle connection stops working, reconnect from **Integrations** to refresh the token for that specific `workspace_url`.
  </Accordion>
  <Accordion title="databricks_execute_sql hangs or times out on a large query">
    Use `databricks_execute_async` instead, then poll `databricks_get_statement_status` / `databricks_get_statement_result` — synchronous execution isn't suited to long-running queries.
  </Accordion>
  <Accordion title="Unity Catalog tools return a permissions error">
    Unity Catalog operations (create/update/delete on catalogs, schemas, tables) require the connected identity to have the appropriate `USE CATALOG`/`CREATE`/`OWNER` privileges — check with a workspace admin if a tool that should work returns 403.
  </Accordion>
  <Accordion title="databricks_run_job_now succeeds but the job fails silently">
    Call `databricks_get_run_output` on the resulting run ID to see the actual task error — the "now" call only confirms the run was triggered, not that it completed successfully.
  </Accordion>
</AccordionGroup>
