# LaunchDarkly

Shanone's LaunchDarkly integration gives your agent 76 tools covering nearly all of LaunchDarkly's feature management platform — flags, environments, segments, experiments, AI Configs, approvals, audit logs, and team/role administration.

## Getting Started

<Steps>
  <Step title="Generate a LaunchDarkly Access Token">
    In your LaunchDarkly account, go to **Account Settings → Authorization** and create a Personal or Service Access Token (SDK/Mobile keys will not work).
  </Step>
  <Step title="Add it to Shanone">
    Open **Integrations** in the Shanone dashboard, select LaunchDarkly, and paste in your Access Token.
  </Step>
  <Step title="Retry your request">
    Once saved, `shanone_execute_tool` calls for `launchdarkly_*` tools will succeed.
  </Step>
</Steps>

## Troubleshooting

<AccordionGroup>
  <Accordion title="launchdarkly_toggle_feature_flag doesn't seem to take effect">
    Flags are toggled per-environment — confirm you're targeting the right `environmentKey` (e.g. `production` vs `staging`), since toggling in one environment has no effect on others.
  </Accordion>
  <Accordion title="launchdarkly_update_feature_flag or launchdarkly_delete_feature_flag returns a conflict/approval error">
    Some LaunchDarkly workspaces require approval workflows for flag changes — use `launchdarkly_create_approval_request_for_flag` and `launchdarkly_review_approval_request_for_flag`/`launchdarkly_apply_approval_request_for_flag` instead of updating directly.
  </Accordion>
  <Accordion title="Access Token works for some tools but not others">
    LaunchDarkly access tokens carry specific role/permission scopes — a token scoped to a single project or reader role will fail on admin-level tools like `launchdarkly_create_custom_role` or `launchdarkly_create_project`; generate a token with broader permissions if needed.
  </Accordion>
</AccordionGroup>
