# Sentry

Shanone's Sentry integration gives your agent 115 tools spanning issue triage, performance tracing, session replay, release health, and org administration (members, SCIM, integrations) — enough to run most day-to-day Sentry workflows without leaving the agent.

## Getting Started

<Steps>
  <Step title="Create a Sentry Auth Token">
    In Sentry, go to **Settings → Developer Settings** and create an Internal Integration or Personal Auth Token with the scopes your workflows need (e.g. `project:read`, `event:read`, `org:read`).
  </Step>
  <Step title="Connect the API key in Shanone">
    Ask your agent to do something with Sentry (e.g. "list unresolved issues in my project"), or add the Auth Token proactively from **Integrations** in the Shanone dashboard. An Organization Slug can optionally be set to avoid repeating it on every call.
  </Step>
  <Step title="Retry your request">
    Once connected, `shanone_execute_tool` calls for `sentry_*` tools will succeed.
  </Step>
</Steps>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Calls fail with a 401/403 even though the token looks valid">
    The Auth Token's scopes must match the endpoint — e.g. `sentry_bulk_update_issues` needs `event:write`, while `sentry_list_projects` only needs `project:read`. Regenerate the token in **Settings → Developer Settings** with the missing scope.
  </Accordion>
  <Accordion title="sentry_list_issues returns an empty list for a project I know has issues">
    Most list tools default to a short time window (Sentry's `statsPeriod`) and to unresolved issues only. Pass an explicit `query`/`statsPeriod` — check `shanone_get_tool_schema` for `sentry_list_issues` for the exact parameter names.
  </Accordion>
  <Accordion title="Organization Slug errors on every call">
    If it wasn't set on the connection, most tools require an explicit `organization_slug` argument per call — set it once on the integration to avoid repeating it.
  </Accordion>
  <Accordion title="sentry_trigger_issue_autofix doesn't return a result immediately">
    Seer autofix runs asynchronously; poll `sentry_get_issue_autofix` for the same issue until the run status is complete.
  </Accordion>
</AccordionGroup>
