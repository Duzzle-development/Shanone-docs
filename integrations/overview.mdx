## How the catalog works

Shanone doesn't register a separate MCP tool for every action of every service — that would be thousands of tools competing for space in your agent's context window. Instead, every integration's tools live in one searchable catalog, and your agent reaches them through three meta-tools:

<Steps>
  <Step title="Search">
    `shanone_search_tools` with a task-shaped query (optionally filtered by `service`)
  </Step>
  <Step title="Inspect">
    `shanone_get_tool_schema` with the exact tool name, to see required/optional arguments
  </Step>
  <Step title="Execute">
    `shanone_execute_tool` with the tool name and a JSON string of arguments — OAuth is handled automatically via a `connect_link` if needed
  </Step>
</Steps>

See [MCP Overview](/mcp/overview) for the full mechanics. The pages below go deeper on a curated set of high-usage integrations — but this is a small slice of what's actually available.

## Scale

Shanone is marketed at **140+ integrations and 10,000+ tools** across its full ecosystem. **269+ integrations are implemented and live** in the backend today, covering the services documented below plus many more (GitLab, Bitbucket, Jira, Confluence, HubSpot, Airtable, Discord, Telegram, Microsoft Teams, Google Calendar/Docs/Sheets/Drive, Stripe, PayPal, Shopify, Datadog, Sentry, Cloudflare, Vercel, OpenAI, Anthropic, and more). If a service you need isn't listed here, ask your agent to run `shanone_search_tools` or `shanone_list_service_tools` with that service's name — it's very likely already registered.

## Connecting an integration

Most integrations use OAuth and don't need to be pre-configured — the first time your agent calls a tool for a service you haven't connected, `shanone_execute_tool` returns a `connect_link` instead of failing. Visit it, authorize, and retry. See the [Quickstart](/quickstart) for a walkthrough, or connect proactively from **Integrations** in the Shanone dashboard.

<Note>
A few integrations (like Ethereum) authenticate with a configured RPC endpoint/API key rather than OAuth — see that integration's page for specifics.
</Note>
