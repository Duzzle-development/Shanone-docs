# Cloudflare

Shanone's Cloudflare integration gives your agent 247 tools spanning nearly all of Cloudflare's platform: DNS, zones, Workers, Pages, R2, D1, KV, queues, Zero Trust Access, AI Gateway, Workers AI, load balancing, and security/audit tooling.

## Getting Started

<Steps>
  <Step title="Create an API Token">
    In the Cloudflare dashboard, go to **My Profile → API Tokens** and create a token scoped with the Zone/DNS/Workers/Pages/etc. permissions you need (or a broader token for full access).
  </Step>
  <Step title="Add it to Shanone">
    Open **Integrations** in the Shanone dashboard, select Cloudflare, and enter the API Token along with your Account ID.
  </Step>
  <Step title="Retry your request">
    Once saved, `shanone_execute_tool` calls for `cloudflare_*` tools will succeed.
  </Step>
</Steps>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Tools return an 'Authentication error' despite a valid token">
    Most Cloudflare tools need both an API Token and an Account ID (and DNS/zone tools additionally need a `zone_id`) — check `shanone_get_tool_schema` for the exact required fields, since account-scoped and zone-scoped resources use different identifiers.
  </Accordion>
  <Accordion title="cloudflare_d1_query / cloudflare_r2_* tools return a permissions error">
    API Tokens are scoped per-product; a token created only with DNS permissions won't be able to call D1, R2, or Workers endpoints. Create a new token with the additional scopes or use a broader account-level token.
  </Accordion>
  <Accordion title="Newly created DNS record isn't resolving yet">
    DNS changes propagate through Cloudflare's edge network, which can take a short time even though the API call itself succeeds immediately — this is expected and not a tool failure.
  </Accordion>
  <Accordion title="cloudflare_create_pages_deployment doesn't reflect the latest code">
    Pages deployments are tied to whatever build/artifact was pushed at trigger time; make sure the underlying Git integration or direct upload actually contains the changes before triggering a new deployment.
  </Accordion>
</AccordionGroup>
